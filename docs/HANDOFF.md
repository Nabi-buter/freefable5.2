# CINDERWAKE — 인수인계 문서 (작업 재개용 요약)

> 이 문서는 세션이 끊겨도 다음 세션이 **이 파일만 읽고** 작업을 이어갈 수 있도록 유지한다.
> 작업을 마칠 때마다 "현재 상태"와 "다음 할 일"을 갱신할 것.

## 1. 게임 한 줄 요약

**CINDERWAKE** — 끝나지 않는 밤의 섬에서 다섯 봉화를 밝히고, 보스 "일식"을 쓰러뜨려 새벽을 되찾는
3D 액션 로그라이트(서바이버류). 브라우저에서 바로 실행되며 모든 에셋(모델·텍스처·효과음·음악)이
코드로 절차적 생성된다. 외부 에셋 파일 없음.

- 한 판 약 10~15분: 이동/대시 → 자동 공격 → 불씨(경험치) 수집 → 레벨업 3택 → 봉화 점화 → 유물 → 보스 → 새벽
- 무기 14종(각 6레벨 + 진화형), 패시브 14종, 유물 18종, 적 10종(지역 전용 3종 포함) + 미니보스 + 최종 보스(3페이즈)
- 캐릭터 7명(각자 고유 능력 2종 중 선택), 지역 4곳, 난이도 3단계, 영구 강화 14종, 업적 27개, 일일 도전, 무한 밤 모드, 한국어/영어

## 2. 기술 스택 / 명령어

- Vite 8 + TypeScript(strict) + three.js 0.187 (런타임 의존성은 three, @fontsource/cinzel 뿐)
- `npm run dev` 개발 서버 · `npm run build` 타입체크+빌드(`dist/`) · `npm test` vitest · `npm run sim` 밸런스 봇
- 밸런스 봇: `npx tsx tests/simbot.ts <판수> <난이도0-2> <캐릭터|all> <실력0-1> <지역> <강화단계> [endless]`
- 배포: `.github/workflows/deploy.yml` (push → build → test → GitHub Pages)

## 3. 구조 (src/)

| 경로 | 역할 |
| --- | --- |
| `sim/` | **렌더링과 완전히 분리된 순수 게임 로직** (Node에서 실행 가능) |
| `sim/defs.ts` | 적·무기·패시브·유물·캐릭터·난이도·영구강화 데이터 테이블 |
| `sim/worldgen.ts` | 시드 기반 섬 생성: 높이 함수, 봉화 위치, 길, 장애물, 장식 |
| `sim/sim.ts` | `Sim` 클래스: 플레이어, 피해 계산, 드롭, 봉화, 메인 스텝, 공간 해시 |
| `sim/ai.ts` | 적 AI 6종, 스폰 디렉터(위협 예산), 미니보스/최종 보스 패턴 |
| `sim/weapons.ts` | 무기 14종 동작, 투사체/장판 업데이트 |
| `sim/choices.ts` | 레벨업·유물·상자 선택지 생성과 적용, 리롤/봉인/건너뛰기 |
| `sim/skills.ts` | 캐릭터 고유 능력 5종(`castSkill`/`updateSkill`), 정의는 `defs.ts`의 `SKILLS` |
| `render/view.ts` | `GameView`: 렌더러, 포스트프로세싱, 카메라, sim→화면 동기화, 이벤트 연출 |
| `render/env.ts` | 지형 메시, 바다 셰이더, 하늘 셰이더(별·오로라·일출), 조명, 지역 팔레트 |
| `render/geo.ts` | 절차적 로우폴리 모델 전부 (적, 플레이어, 나무, 유적, 봉화…) |
| `render/props.ts` | 장애물/장식 인스턴싱 배치 |
| `render/actors.ts` | 플레이어 모델 애니메이션, 적 인스턴스 렌더러 |
| `render/fx.ts` | 파티클, 지면 데칼(지형 추종), 번개 리본, 2D 오버레이 텍스트 |
| `render/materials.ts` | 공용 머티리얼(글로우·바람·피격 플래시 셰이더 패치) |
| `audio/audio.ts` | Web Audio 절차적 효과음 + 생성형 적응 음악 |
| `ui/ui.ts`, `ui/style.css`, `ui/icons.ts` | DOM UI 전체(타이틀/준비/상점/기록/설정/HUD/모달), SVG 아이콘 |
| `core/` | 입력(키보드·마우스·게임패드·터치), 세이브, 다국어, 업적/해금, RNG/노이즈 |
| `main.ts` | 앱 상태 머신과 게임 루프 |

핵심 규칙:
- sim은 three를 import하지 않는다. 화면/소리는 `sim.events`(SimEvent[])를 소비해서 만든다.
- sim 좌표는 (x, z) 평면. 높이는 `world.height(x,z)` 순수 함수(렌더러는 `HeightField`로 캐시).
- 모델은 +X를 바라보게 만들고 `rotation.y = -facing`.
- 다국어 문자열은 전부 `core/i18n.ts`의 `[ko, en]` 쌍. 무기 레벨 설명은 스탯 테이블에서 자동 생성.

## 4. 테스트 방법

- 로직: `npm test`, 밸런스: `npm run sim`
- 화면: `npx vite preview --port 4173` 후 Playwright(사전 설치됨)로 스크린샷.
  헤드리스는 소프트웨어 렌더링이라 초당 2프레임 수준 → `?debug&q=low` 사용, `window.warp(초)`로 시뮬 빨리감기,
  `window.app`으로 상태 접근, `window.cheat.{level(n),boss(),win(),die(),lightAll()}`로 장면 바로가기.
  스크린샷은 `shots/`(gitignore). 느린 프레임 때문에 키 입력은 `app.state`/`app.ui.modal`을 폴링한 뒤 보낼 것.

## 5-1. 난이도 곡선 (2026-11-18, 사용자 피드백 "초반 어렵고 후반 쉬움" 반영)

`Sim.curve(early, late)`가 스폰량·적 체력·적 피해에 곱해진다. 처음엔 `early`배(스폰 0.65·피해 0.6·체력 0.7)에서 9분에 걸쳐 1로 오르고,
진행도(10분 이후 분, 봉화 3개째부터 1.5/개, 보스 등장 시 4.5) 1당 `late`(스폰 +8%·피해 +15%·체력 +12%)씩 올라간다. 보스 체력 시간 계수 0.045→0.08.
측정(120판, 봇 0.7, 지역 4곳): 9분 전 사망 14→7판, 승리한 판의 9분 이후 최저 체력 중앙값 93%→61%, 승률 69%→67%.
봇에 `lateHp`(9분 이후 최저 체력) 지표 추가. 측정 스크립트 예: 4지역 30판씩 돌려 사망 시각 분포와 lateHp 중앙값을 비교.

## 7. 알려진 문제 / 주의

- **터치 검증은 반드시 실제 탭으로**: `page.click`은 마우스 이벤트라 터치 버그를 못 잡는다. 2026-11-17에 `Input`이 `document.body`의
  모든 터치에 `preventDefault`를 걸어 모바일에서 버튼이 전혀 눌리지 않던 문제가 배포 후에야 발견됨 → 캔버스 위 터치만 가로채도록 수정.
  `tests/tools/touch-check.cjs`(미리보기 서버 4173 필요)가 세로·가로에서 탭/스틱/능력/일시정지를 확인한다.
- 휴대폰(터치 전용 기기)은 첫 실행 기본 그래픽이 '보통'(`defaultQuality`), 세로일 때 타이틀에 가로 전환 안내 표시
- 휴대폰에서는 출발 시 전체 화면 + 가로 고정을 시도한다(`goLandscape`, 지원하지 않는 브라우저는 세로 레이아웃 그대로 동작).

- 헤드리스 테스트는 매우 느리다(버그 아님). 타이밍 의존 테스트는 `warp`를 쓸 것.
- `UnrealBloomPass` 임계값 0.9: HDR 색(>1)만 번진다. 새 이펙트 색은 1~3 범위로.
- 포인트 라이트 개수는 고정(플레이어 1 + 거점 3 + 섬광 2). 늘리면 셰이더 재컴파일로 끊김 발생.
